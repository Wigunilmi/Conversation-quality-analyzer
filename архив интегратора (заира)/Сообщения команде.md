# Сообщения команде: Data Challenge (Freedom Broker CQA)

## Всем
Код проекта в архиве `cqa-scaffold.tar.gz` (распаковать двойным кликом), позже будет в репозитории GitHub `Wigunilmi/data-challenge-bioc-team`.
Запуск: `cp .env.example .env` → `npm start` → открыть http://localhost:3000 (нужен Node 22.9+).

## Бэкенду
Фронт и логика оценки готовы. На тебе API на FastAPI и база.
1. `API_CONTRACT.md` — все эндпоинты и форматы, которые ждёт фронт. Сделай их один в один, тогда фронт заработает без изменений.
2. В `backend/cqa/` уже готово на Python: `scoring.py` (подсчёт баллов), `sanitize.py`, `facts.py`, `evaluator.py` (вызов модели), `audio.py` (mp3 звонка). Тесты: `cd backend && pip install pytest && python -m pytest -q` — должно пройти 479.
   Оценка в эндпоинте: `result = await run_in_threadpool(evaluate, conversation, checklist)`.
3. Эталон поведения — `server.mjs`. Запусти `npm start` и смотри, что отдаёт каждый эндпоинт.
4. Важно:
   - итоговый балл НЕ храним в базе, считаем при каждом чтении (`view()` в `server.mjs`);
   - в каждой оценке храним `checklist_id` и `checklist_version`;
   - нужна постоянная база: Postgres/Supabase или сервер с диском (на Vercel диска нет).
5. Как сервер будет доступен по публичному адресу — скинь адрес, выложим фронт на Vercel.

## ML
Главная задача — точность, это основной критерий отбора.
1. В файл `.env` в папке проекта (ключ никому не отправлять):
```
LLM_BASE_URL=https://api.meta.ai/v1
LLM_MODEL=muse-spark-1.3
LLM_API_KEY=твой_ключ
LLM_PRICE_IN=1.25
LLM_PRICE_OUT=4.25
```
2. `npm start` → «Диалоги» → DEV → «Загрузить набор» → «Оценить».
3. Проверка казахского: на «Обзоре» карточка «Согласованность языков» должна показывать 80% и выше.
4. Эталон: открыть диалог → вкладка «Эталон» → проставить правильный ответ по каждому критерию строго по чек-листу → «Сохранить и к следующему». Нужно 15–20 диалогов: около 8 RU, 4 KZ, 4 EN, 2 звонка. Обязательно: `p1-ru-022`, `p1-ru-023`, `p1-kz-013`, `p1-en-013` (в них грубые ошибки).
5. На «Обзоре» появится «Точность против эталона». Скинь скрин, доработаем промпт (`prompts/judge_system.md`).

## Ответы организаторов (из чата)
- 10 контрольных транскриптов придут через тот же API, что и DEV. Распознавать речь самим не нужно.
- Для звонков действуют те же 8 критериев, адаптированные под устную речь: 06 — логика, понятность, паузы; 04 — ответил ли на вопросы, не дал ли ошибочной информации.
- Нужна гибкая система с несколькими чек-листами, в том числе для звонков. Это у нас есть.
- Любая модель и любые фреймворки разрешены, кроме захардкоженных результатов.
- Репозиторий — публичный, у каждой команды свой.
